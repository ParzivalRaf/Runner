# Как поставить Runner на iPhone

Пошагово, с нуля. Первый раз займёт около часа, дальше — пара минут.

Это официальный путь от Apple: бесплатное провижининг для запуска своих
приложений на своих устройствах. Никакого джейлбрейка, TestFlight не нужен
(он вообще недоступен без платного аккаунта за $99/год).

---

## Что понадобится

- Mac с Xcode (уже скачан)
- iPhone и кабель
- Apple ID — обычный, тот же, что на телефоне. Платить не надо.

---

## Часть 1. Переключить проект на iOS

Сейчас проект собран под Android — это видно в заголовке окна Unity:
`Game - Runner - Android`.

1. **File → Build Profiles**
2. В списке слева выбрать **iOS**
3. Нажать **Switch Platform**

Unity переимпортирует все текстуры и шейдеры под новую платформу.
Займёт несколько минут, окно может подвиснуть — это нормально, жди.

Готово, когда в заголовке окна появится `Runner - iOS`.

---

## Часть 2. Настроить проект

**Edit → Project Settings → Player**, вкладка iOS (иконка яблока).

Раскрой **Other Settings** и проверь три поля:

| Поле | Что поставить | Зачем |
|---|---|---|
| **Bundle Identifier** | `com.RafaelGames.Runner` | Сейчас там мусор от шаблона URP: `com.Unity-Technologies.com.unity.template.urp-blank`. С ним подпись не пройдёт. |
| **Automatically Sign** | галочку поставить | Xcode сам выпустит сертификат. |
| **Signing Team ID** | пока пусто | Заполним в Части 4, когда узнаем номер. |

Остальное не трогай — ориентация Portrait и прочее общие для всех платформ
и уже настроены.

---

## Часть 3. Собрать Xcode-проект

Важно понимать: **Unity не делает готовое приложение для iPhone.**
Она делает проект для Xcode, а уже Xcode собирает из него приложение.
Поэтому шагов два.

1. **File → Build Profiles → iOS → Build** (не «Build And Run», первый раз идём вручную)
2. Unity спросит, куда сохранить. Создай папку **рядом с проектом, а не внутри него**:
   `~/Desktop/Runner_iOS`
   Внутрь проекта класть нельзя — Unity начнёт импортировать собственный билд
   как ассеты и всё сломается.
3. Ждёшь. Первый билд долгий — IL2CPP переводит весь C# в C++. 5–15 минут.

Когда закончится, в папке `Runner_iOS` появится `Unity-iPhone.xcodeproj`.

---

## Часть 4. Подписать в Xcode

1. Открой **Unity-iPhone.xcodeproj** двойным кликом — запустится Xcode.

2. Добавь свой Apple ID:
   **Xcode → Settings → Accounts → «+» → Apple ID** → войди.
   После входа в списке появится **Personal Team** — это и есть твой
   бесплатный аккаунт разработчика.

3. В левой панели Xcode кликни на самый верхний элемент **Unity-iPhone**
   (с иконкой синего чертежа). Откроются настройки проекта.

4. В центре выбери таргет **Unity-iPhone** → вкладка **Signing & Capabilities**.

5. Поставь галочку **Automatically manage signing**, в **Team** выбери
   свою Personal Team.

6. Xcode покажет **Bundle Identifier** и должен перестать ругаться красным.
   Если пишет, что идентификатор занят — поменяй на что-нибудь уникальное,
   например `com.RafaelGames.Runner2`.

### Про Team ID

Он **не нужен для первой сборки** — подписи в Xcode достаточно. Это только
удобство на будущее: с ним заработает Build And Run прямо из Unity, без
захода в Xcode.

В новых версиях Xcode в панели Apple Accounts его больше не показывают.
Достать можно после первой успешной сборки, любым из двух способов:

- В Терминале:
  `grep -m1 DEVELOPMENT_TEAM ~/Desktop/Runner_iOS/Unity-iPhone.xcodeproj/project.pbxproj`
- В Xcode: верхний **Unity-iPhone** → **Build Settings** → в поиске набрать
  `Development Team`

Строка из 10 символов вроде `A1B2C3D4E5`. Вписывается в Unity:
Project Settings → Player → iOS → **Signing Team ID**.

---

## Часть 5. Поставить на телефон

1. Воткни iPhone в Mac кабелем.

2. На телефоне выскочит **«Доверять этому компьютеру?»** — жми **Доверять**
   и введи код-пароль.

3. В Xcode сверху, рядом с кнопкой ▶, выбери своё устройство
   (не симулятор — именно название твоего айфона).

4. Жми **▶ (Run)**.

Первый раз он упрётся в две вещи, обе решаются на телефоне:

### Режим разработчика

Xcode напишет что-то вроде *«Developer Mode disabled»*.

На телефоне: **Настройки → Конфиденциальность и безопасность → Режим
разработчика** → включить → телефон попросит перезагрузиться → после
перезагрузки подтвердить.

> **Если пункта «Режим разработчика» нет** — это нормально. Он появляется
> только после того, как телефон хоть раз подключался к Xcode с попыткой
> установки. Просто нажми Run ещё раз, потом иди искать.

### Доверие сертификату

При первом запуске приложение выдаст *«Ненадёжный разработчик»*.

На телефоне: **Настройки → Основные → VPN и управление устройством** →
найди свой Apple ID → **Доверять**.

5. Запусти игру с домашнего экрана. Всё, она стоит как обычное приложение,
   работает без кабеля и без интернета.

---

## Дальше: как пересобирать

Когда Team ID вписан в Unity, цикл становится коротким:

**File → Build Profiles → iOS → Build And Run** — Unity сама соберёт,
откроет Xcode и поставит на телефон. Пара минут.

Иногда Xcode всё же ругается на подпись после чистой пересборки. Тогда
открой `Unity-iPhone.xcodeproj` руками и один раз повтори Часть 4.

---

## Ограничения бесплатного аккаунта

Про них надо знать заранее, чтобы не удивляться.

- **Приложение перестаёт запускаться через 7 дней.** Лечится повторным Run
  из Xcode — две минуты. Прогресс в игре при этом не теряется, сейв остаётся.
- **Не больше трёх своих приложений** на устройстве одновременно.
- **Раздать игру кому-то ещё нельзя.** Ни учителям, ни одноклассникам.
  Для этого нужен платный Apple Developer Program ($99/год) — или Android,
  где это просто файл APK.

Последний пункт стоит держать в голове: если цель в том, чтобы в игру
поиграла школа, iOS этого не даст. Дешёвый б/у Android-телефон решает
вопрос раздачи полностью и стоит дешевле годовой подписки Apple.

## Что проверить в первую очередь на телефоне

Свайпы до этого момента тестировались только клавиатурой. Именно они —
главное, ради чего мы лезем на устройство.

1. **Порог свайпа.** Слишком большой — придётся возить пальцем через пол-экрана,
   персонаж будет казаться тормозным. Слишком маленький — случайные касания
   будут менять полосу. Крутится: Player → Swipe Detector → **Min Pixel Distance**
   (сейчас 50).
2. **Момент срабатывания.** Жест засчитывается, как только палец прошёл порог,
   а не когда ты его отпустил. Так задумано — так отзывчивее. Проверь,
   не мешает ли это на практике.
3. **Быстрая серия свайпов.** Влево-влево-вверх подряд. Все три должны пройти.
4. **Свайп во время прыжка.** Полосу менять в воздухе можно, это не баг.
5. **Тап по кнопкам** меню и паузы — не промахивается ли палец, не слишком ли
   близко к краю экрана.

Отдельно посмотри на **FPS**: Player → Debug Hud → галочка **Show**.
На телефоне должно держаться 60.
